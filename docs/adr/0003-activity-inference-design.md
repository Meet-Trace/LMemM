# ADR 0003: Deterministic activity inference, design and PR 2A (Step 2, PR 2)

Status: proposed. The full design (revisions 1 to 5, sections 1 to 14) is the Claude Doc "Step 2 PR 2: Deterministic Activity Inference - Design". This ADR records what is decided and what PR 2A builds. PR 2A contains **no inference**: no scoring, no assignment, no grouping, no model call, no live integration, no change to the tracker, the Moment schema, `memory.json`, the project finder or `MOMENT_LOG`.

## What PR 2 will be (decided)
- **Offline batch replay only.** Public entry: `replay(infer, records, params)` in `src/activity_contract.py`, moment records in, result out, a pure function of the persisted Moments (at most 48 h). The inference proper is `infer(prepared, params) -> result`, where `prepared` is `activity_input.Prepared`: records already validated (every integrity rule), de-duplicated and canonically ordered. Output goes only to a folder the user names; nothing is written to the data directory. No online engine, provisional assignments, revision history or finalisation lag. No typed, pasted or clipboard text is read or stored. No model, no CPU judge.
- **Why the inference takes `Prepared`.** This replaces the earlier wording `infer(moment_records, params)`. Validation is a precondition, not part of inference: it must run exactly once, on the original records, with every rule including the capture-clock part of V4. The invariants translate and scale time while keeping visit ids; if the inference took raw records it would have to re-validate re-timed copies, either failing them on the capture-clock rule or receiving a flag that lets it skip a check. With `Prepared`, the inference can only ever see validated input, and the harness, not the inference, decides how re-timed copies are validated. The records-in contract the design promised is kept by `replay`.
- **The visit is the assignable unit.** Every visit carries an `internal_shift` flag (reported, lowers confidence, never splits).
- **States.** `assigned`, `tentative`, `ambiguous`, `unassigned`, each with a reason. Only `assigned` has an activity id and enters the predictions; the others are scored as singletons. A seed is `assigned` with reason `seed`; coverage is reported with and without singleton activities.
- **Activity ids** are a hash of the earliest final member's visit id. No counters; no promise across different replay windows.
- **Evidence.** Same branch is soft context; PR/issue identity, document identity and version lineage are separate rules. Version lineage cannot assign alone and needs content corroboration. A shared artifact is a candidate link, not a verdict. Specificity is computed from observable features only, never from assignments.
- **Passes.** Pass 1 creates conservative anchors (cannot-links checked first, two independent evidence sources, no time or neighbour context); Pass 2 adds time and neighbour context from earlier assignments only; Pass 3 merges. Assignments are only added, never withdrawn, and no activity may contain a cannot-linked pair.
- **Time.** No feature uses absolute time. Translating all timestamps (by any amount, either sign) changes nothing; scaling all timestamps and all time parameters together (any factor above zero) changes nothing; changing timestamps alone may change membership. Every seconds-valued parameter is declared. Visit ids never change under these transformations.
- **Status** (`candidate`, `active`, `paused`, `dormant`) is reporting only and never influences assignment.
- **Token classes** (for the later content similarity) are mutually exclusive and hub takes precedence: hub if `df > 0.2 N`, single if `df == 1`, rare if `2 <= df <= max(3, ceil(0.05 N))`, else common, with `df` the number of distinct visits and `N` the number of eligible visits.

## What PR 2A builds
- `src/activity_input.py`: reads a folder of moment JSONL read-only; drops identical duplicates; fails on the same id with different content, on unsupported schema, on fields outside the Moment schema (so nothing typed can enter), and on visit-integrity violations V1 to V5 (constant fields, id and seq structure, timestamps and gaps, visit-id second, context chain). V4 is described below. Any such failure writes no output and exits with code 3; messages carry only visit ids, check codes, field names and moment ids, never screen content. Half-written lines are skipped and counted (`strict` fails instead). Canonical order is `(t_start, seq, visit_id, id)`.
- `src/activity_contract.py`: the result contract, the activity id function, `ReplayParams` with declared time parameters, `validate_result`.
- `src/activity_abstention.py`: coverage with and without singletons, precision on assigned visits, recall over eligible visits, the four state rates with reasons, mixed-gold visits (counted apart, never given a label, excluded from primary scores), `internal_shift` against moment-level gold with boundary agreement, a visit-level ceiling, and baselines compared on the same visits only. A visit is pure when its labelled moments share a label, mixed-gold when they do not (a noise moment beside an activity counts as mixed).
- `tests/activity_fixtures.py`: a seeded generator of valid Moment records with gold, for the scenarios in the design, with a noise model that never changes ids, times or visits.
- `tests/activity_harness.py` and `tests/activity_stubs.py`: invariant checks (determinism, order and duplicate invariance, translation, joint scaling, status independence, forget consistency, no typed text, ids, totality, cannot-links, app-name invariance, a directional helper), run against structural stand-ins that pass and against deliberately broken ones that must be caught.

## Visit ids and check V4 (decision)
`src/moments.py` builds a visit id once, when the visit is created: `f"{prefix}{int(t)}-{n}"` (prefix `v` unless `clock_id` is given; `t` is the first frame's capture-clock time, which is also the first moment's `t_start`; `n` is a per-process counter that restarts at 1). It is stored, never rewritten (forget only scrubs pointers to it), and used as a key: moment ids are `<visit_id>.<seq>` and activity ids will be a hash of it. It is therefore an **immutable label whose content records the capture clock at creation**, not a timestamp to be translated with the data. Consequence: a test that moves timestamps while keeping ids is deliberately modelling data whose clock no longer matches its labels.

V4 has two parts, and the absolute one is the primary check:
- **Absolute, on by default** (`check_capture_clock=True`): a visit that still has its first moment has `int(t_start) == embedded second` (stronger than the earlier one-sided bound, because the Moment layer derives both from one reading); a visit whose oldest moments were dropped by retention has an embedded second no later than `int(t_start)` of its first remaining moment.
- **Relative, always on**, unchanged by translating or scaling time. It guarantees only this: the id has the form `<prefix><second>-<n>` with `n >= 1`, and among visits that still have their first moment and share a prefix, one that starts strictly later never has a smaller embedded second. The comparison is strict, with no tolerance, so it holds under every positive scaling of time (genuine data cannot violate it: a later start `tb > ta` with a smaller second `sb < sa` would need `tb < sb + 1 <= sa <= ta`). **It does not catch**: counter suffixes swapped between visits that start in the same second; ids exchanged between visits whose seconds are equal or whose order stays consistent; ids all shifted together; foreign ids whose seconds happen to fit; anything about visits whose first moment was dropped; a duplicate counter across restarts (that shows up as a conflicting id or as V1). The test `test_relative_v4_limitations` pins these limits, so the guarantee is explicit.

**V3 tolerance.** The integrity checks on one visit's moments use float slack `tol = TOL_REL * max_intra_visit_gap_s` with `TOL_REL = 1e-6`, and nothing else: a moment is invalid if `t_end - t_start < -tol`; neighbours overlap if `t_start(next) - t_end(prev) < -tol`; a gap is too large if that difference exceeds `max_intra_visit_gap_s + tol`. Every comparison uses a difference of two timestamps, so translation cancels exactly and no absolute timestamp enters; `tol` is proportional to a time-valued parameter, so under joint scaling by any `k > 0` the differences and `tol` both scale by `k` and no outcome changes. There is no fixed floor, so arbitrarily small factors work, and the slack (0.3 ms at the default 300 s) stays far below any genuine overlap, negative duration or excess gap. `max_intra_visit_gap_s` must be a positive finite number. **Numerical limitation:** the relative tolerance accounts for floating-point rounding only while timestamp magnitudes remain small relative to `max_intra_visit_gap_s` (roughly below `4e9 * max_intra_visit_gap_s`); beyond this range, floating-point precision may cause valid boundary cases to be rejected. This is a floating-point representation limit, not a violation of the mathematical scale-invariance argument, and it is deliberately documented rather than fixed by enlarging the tolerance, which would risk accepting genuine overlaps and excess gaps.

The absolute part is switched off in exactly one place: the harness, for records it has re-timed on purpose. The harness validates the **original** records with every rule, and the translated or scaled copies with every rule except that part (all of V1 to V3, V5 and the relative part of V4 still run on them), then checks that outcomes, activity ids and member mappings are identical. Inference receives validated `Prepared` input, so it never sees the flag, and `replay` takes no options and always validates strictly, including the absolute part of V4; only the harness prepares re-timed copies with `check_capture_clock=False` and calls `infer(prepared, params)` directly. Translation uses offsets of both signs and scaling uses factors below and above 1; time-valued integrity limits (`max_intra_visit_gap_s`) scale with the other time parameters.

What this accepts that the pure-absolute rule would not: nothing for real loads, because the CLI will call `load()` with the default. What it costs: the invariant harness does not run the absolute part on re-timed input (it is covered by its own tests on untouched data), and a dataset whose ids are all consistently shifted together is only caught by the absolute part.

## PR 2B: visit features and evidence (built; no scoring)
`Prepared -> extract_features -> FeatureSet -> build_evidence -> EvidenceSet`, in `src/activity_features.py` and `src/activity_evidence.py`. Pure and deterministic; reads only fields already in the Moment schema; writes nothing; decides nothing. PR 2C scores and assigns from these two objects without reading a raw Moment again.

**FeatureSet.** Per visit: `artifacts` (kind, normalised key, class H1/I/L, fixed specificity prior, scope, sources, moment ids), `namespaces` (domain, section, repo, project, branch; soft; a branch only when unambiguous), `tokens` (screen-derived words with a source weight and a `generic` flag), `context_words` (title, target and URL words, kept apart so one text is not counted twice), `quality` and its parts, `glance`, `weak_evidence`, `flag_reasons`, `internal_shift` (descriptor), timing as differences only, and `issues` (optional fields that were missing or malformed and ignored, by name). Set-level: document frequency, token class (`single`/`rare`/`common`/`hub`) and idf over eligible visits, and per-artifact visit and session counts (the observable inputs to artifact promiscuity). **EvidenceSet.** Records of type `shared_artifact` (class I), `shared_identity` (class H1; `match` = exact, unscoped_number, number_only), `shared_lineage` (class L), `shared_namespace` (class N), `shared_tokens` (only for pairs sharing a rare, non-generic word) and `cannot_link` (`x_pr`, `x_branch`; `active` is false when a raw override applies and the reason is kept). Each has source (earlier visit), target, category, key, detail, the moment ids on both sides, how it was observed and the lower quality. `conflicts()` lists pairs with both positive evidence and an active restriction; both stay in the set.

**Decisions.** (1) Token classes follow the ADR cutoffs; `single` (df 1) is decided before `hub`, because a token seen once cannot be a hub (read literally the ADR would call it one for N < 5), and hub beats rare. (2) A visit is named by what it is (its kind, URL, document id, target), never by identifiers seen in its content; a glance is short, single-frame and unnamed. (3) Weak evidence is low quality or no distinctive (non-generic) content word, so a page of only generic words is weak however long it lasted. (4) `internal_shift` compares the first moment with later moments whose digest text differs; it cannot see a change the stored digest never recorded (a full page replacement leaves one moment with the first topic's digest). (5) X-PR needs each visit to carry exactly one scoped number in the repository and the declared dwell; X-BRANCH has no dwell condition; integration branches (`main`, `master`, `develop`, `trunk`) never restrict. (6) Time-valued parameters added: `cannot_link_min_dwell_s`, `session_gap_s` (declared, scaled by `FeatureParams.scaled`); retention is also a time limit and scales with the data in the invariants.

**Not decided here, flagged for 2C.** Weights, thresholds and the confirmation rules; the context-diversity half of artifact promiscuity (it needs neighbour bags, available from the FeatureSet); how the unscoped `#N` evidence is weighed against the project-equals-repository heuristic. **Unverified on real data:** a branch in an editor window title `project (branch)` is a pattern the fixtures show; real editors may not display it. The fixtures record provenance as `{"ocr": n}`, not the real `ax_only/ocr_only/agreed/differed`; unknown keys are treated as no information (quality 0.8).

## Limits
Synthetic fixtures test logic, not truth. Rare and hub cutoffs, thresholds and weights are placeholders until the fixtures and later real labels calibrate them. The visit-integrity checks cannot detect a collision between two unrelated visits with identical item, sequence and times.

# ADR 0004: Visit features and evidence (Step 2, PR 2B)

Status: proposed. Builds on ADR 0003. PR 2B contains **no inference**: no scoring, no assignment, no clustering, no model, no persistence, no change to the Moment or Observation schemas, the contract, the project finder or the tracker. It turns `Prepared` visits into a `FeatureSet` and an `EvidenceSet` that PR 2C consumes without reading a raw Moment again. Code: `src/activity_features.py`, `src/activity_evidence.py`.

## Shape
`Prepared -> extract_features(prepared, params, fparams) -> FeatureSet -> build_evidence(feature_set, params, fparams) -> EvidenceSet` (`analyse()` does both). Pure and deterministic; frozen dataclasses, tuples and read-only mappings; canonical ordering; the input is never modified. It reads only Moment fields (`item_id, kind, target, window, url, digest, provenance, n_frames`, timestamps); typed, pasted or clipboard text cannot reach it (the input check refuses unknown fields).

**VisitFeatures:** `artifacts` (kind, normalised key, class H1 / I / L, fixed specificity prior, scope, sources, moment ids), `namespaces` (domain, section, repo, project, branch; soft), `tokens` (screen-derived words with a source weight and a `generic` flag), `context_words` (title, target and URL words, kept apart so one text is not counted twice), `quality` and its parts, `glance`, `weak_evidence`, `flag_reasons`, `internal_shift` (descriptor), timing as differences only, and `issues`. **FeatureSet:** document frequency, token class and idf over eligible visits, and `artifact_stats`. **Evidence** types: `shared_artifact` (I), `shared_identity` (H1; `match` exact / unscoped_number / number_only), `shared_lineage` (L), `shared_namespace` (N), `shared_tokens` (only for pairs sharing a rare, non-generic word), **`distinct_identity`** (a fact: different PR / issue numbers in one repository, or different non-integration branches in one scope) and `cannot_link` (a restriction; `x_pr`, `x_branch`).

## Cannot-link completeness (how it is guaranteed)
1. **Restrictions are generated by their own function (`_restrictions`), separate from support evidence.** The performance bound `max_group` (a successor window for keys shared by many visits) applies to support evidence only; no group-size cutoff exists in restriction generation.
2. **Every candidate pair is enumerated.** For each repository, all visits with exactly one scoped PR / issue number are paired; for each repository-backed scope, all visits with one observed non-integration branch are paired.
3. **Fail closed, not silent.** If the number of pairs to enumerate would exceed `max_restriction_pairs` (default 500,000), `build_evidence` raises `ConstraintOverflowError` before producing anything. An `EvidenceSet` therefore either holds every required cannot-link or does not exist.
4. **A consumer-side check.** `EvidenceSet.constraints_complete` and `constraint_pairs_considered` record the guarantee, and `require_complete_constraints()` raises `ConstraintsIncompleteError` for a set that is not known to be complete. PR 2C must call it before assigning any visit.
5. **Tests:** groups of 80 mixed-branch visits (1,600 restrictions) and 105 mixed-PR / issue visits (3,675) keep every pair, and the result is identical for `max_group` 200, 40, 3 and 2; the overflow limit fails at one pair short and succeeds at exactly enough; support truncation is reported in `truncated` and never lists a restriction.

## What may generate what
| Source | Support evidence | Cannot-link |
|---|---|---|
| Scoped PR / issue (code-host URL: repository + number) | `shared_identity` (same number), `distinct_identity` (different numbers) | `x_pr` (see the decision below) |
| Unscoped "#N" in identifiers or a title | `shared_identity` (`unscoped_number`, `number_only`) | never |
| Branch from a code-host URL `.../tree/<one segment>` (**repository-backed**, scope `repo:<host/owner/repo>`) | `shared_namespace` (same branch), `distinct_identity` | `x_branch` (same repository, both non-integration) |
| Branch from an editor window title `project (branch)` (**workspace-derived**, scope `project:<name>`) | `shared_namespace`, `distinct_identity` (source `window`) | **never**: a project or workspace name is not a globally unique repository identity |
| Commit sha | `shared_lineage` (L) | never |
| Domain, section, repo, project | `shared_namespace` (N) | never |
| Branch inside a blob URL, or `.../tree/a/b` | nothing (a slash cannot be told from a path) | never |

A repository page and an editor title are never compared for restrictions, even when the project is named like the repository.

## Different PR / issue numbers: decision
The original, approved design (ADR 0003 "no activity may contain a cannot-linked pair"; the PR 2A fixture `pr_numbers_differ`, whose `cannot_link` expects a restriction; design v4 section 6.2) treats two different PR / issue numbers in one repository as a **conditional cannot-link**: a PR is a task-scoped artifact, and the restriction is lifted by a raw override (a shared identity, or at least two shared rare words) and needs each visit to last `cannot_link_min_dwell_s`. The review's objection is real: a larger activity can span several PRs (stacked PRs, a release), and a wrong restriction **fragments** one activity into two; its absence risks **merging** two tasks.
Decision recorded here: **the original architecture is kept as the default**, and both views are produced. `distinct_identity` is always emitted (a fact, independent of dwell and overrides), and the `x_pr` restriction is controlled by `FeatureParams.x_pr_restricts` (default `True`). With `False`, `x_pr` records are kept but inactive (`inactive_reason: x_pr_not_a_constraint`), so PR 2C works from the fact alone. This needs the owner's confirmation; flipping it changes behaviour only through that one parameter.

## Specificity heuristics (UNCALIBRATED)
Computed per artifact from raw features only, never from assignments. Every parameter below is a placeholder; every output is a heuristic until calibrated on labelled data. They are reported in `FeatureSet.artifact_stats` next to the fixed prior; PR 2B decides nothing with them.
- **Sessions.** Visits of one artifact in canonical order; a new session starts when `t_start - (largest t_end so far) > session_gap_s` (default 1800 s, time-valued, scales with the data).
- **Recurrence** `recurrence(a) = clip((sessions - 1) / R, 0, 1)` with `R = recurrence_sessions` (5). 0 for one sitting, 0.2 for two, 1 from six.
- **Volatility** over the artifact's visits that have at least `volatility_min_tokens` (4) distinctive (non-generic) tokens, at most `volatility_max_visits` (30) of them in canonical order: with bags `b_i(t) = source_weight(t) * idf(t)`, `volatility(a) = clip(1 - mean over all unordered pairs (i < j) of cos(b_i, b_j), 0, 1)`; identical content gives 0, no common word gives 1. With fewer than two qualifying visits it is **undefined**: reported as `0.0` with `volatility_defined = False`.
- **Effective specificity** `eff(a) = prior(kind) * (1 - volatility_weight * volatility) * (1 - recurrence_weight * recurrence)`, weights 0.5 and 0.5, so `0 <= eff <= prior`.
- **Tested:** the boundary values (sessions 0 / 1 / 2 / 6 / 7; undefined, identical and disjoint bags; the 3-versus-4-token threshold; weights 0 and 1), averaging over three and four bags, order independence, monotonicity in each input, range on every fixture, and sensitivity to `session_gap_s` (recurrence changes, volatility does not).
- **Limit:** the context-diversity half of artifact promiscuity (design 3.3) is not computed here; it needs neighbour bags, which PR 2C can build from the FeatureSet. Whether these two quantities match the design document's section 13.3 ("prior x pattern x volatility x recurrence") cannot be checked from the repository; there is no `pattern` factor here.

## Other decisions
1. Token classes use the ADR cutoffs (`hub_share 0.2`, `rare_share 0.05`, `rare_floor 3`) with exact integer arithmetic; hub beats rare; **`single` (df 1) is decided first**, because a token seen in one visit cannot be a hub (read literally the ADR would call it one for N < 5). Needs confirmation.
2. A visit is named by what it is (kind, URL, document id, target), never by identifiers seen in its content; a glance is short, single-frame and unnamed. Weak evidence is low quality or no distinctive (non-generic) word.
3. `internal_shift` compares the first moment with later moments whose digest text differs; it cannot see a change the stored digest never recorded (a full page replacement leaves one moment with the first topic's digest).
4. `search_query` is class I (identity); only PR / issue identity is class H1 in the merged ADR.
5. Time-valued parameters are declared (`cannot_link_min_dwell_s`, `session_gap_s`, plus `ReplayParams.glance_dwell_s` and `internal_shift_min_dwell_s`); retention also scales with the data in the invariants.

## Deviations from the PR 2A fixtures (stated, not hidden)
- The fixture `branches_alternating` expects a cannot-link between two editor visits whose **window titles** carry different branches. Under the repository-identity rule above that pair gets a `distinct_identity` fact (source `window`) and **no restriction**; only the repository-backed pair is restricted. The evidence test records this exactly and requires the unmet expectation to be a workspace-derived one.
- The fixtures give provenance as `{"ocr": n}`, not the real `ax_only / ocr_only / agreed / differed`; unknown keys are treated as no information (quality 0.8).
- A branch in an editor title is a pattern the fixtures show; real editors may not display it. Branch information from URLs is the dependable source.
